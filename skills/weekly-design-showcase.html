Weekly design showcase

Picks the one project with the most momentum this week, then drafts a Slack post and a two-minute Loom outline.

Installation

  1. Save the skill below as SKILL.md inside a folder named weekly-design-showcase.
  2. Claude desktop: zip the folder, rename it to weekly-design-showcase.skill, and add it under Settings > Skills.
  3. Claude Code: place the folder at ~/.claude/skills/weekly-design-showcase/.
  4. Connect Slack, your issue tracker and Figma.
  5. Replace every {{PLACEHOLDER}} with your name, email, channel and timezone.

Usage

Run it Thursday afternoon. It drafts for review and never auto-sends.

/weekly-design-showcase
/weekly-design-showcase showcase the onboarding project instead
make it lean mode

your timezone is {{TIMEZONE}}. "This week" = Monday 12:00am through Thursday at the time the task runs.

## Step 1: Auto-pick the project to showcase

Pull activity from the last 7 days across these sources and identify the project where you had the most meaningful momentum:

1. **Linear**. Use list_issues for issues assigned to {{YOUR_EMAIL}}. Look at issues that moved to Done or are deep In Progress this week. Group by project/team.
2. **Figma**. Use whoami to confirm identity, then check files you edited or commented on this week. Note which files had the most activity.
3. **Slack**. Use slack_search_public_and_private to find threads where you posted designs, got feedback, or led discussion this week. Group by channel/topic.
4. **Running List**. Check the persistent running list for completed items (✅) from this week. These are signals for what you herself considered shipped.

**Selection logic:** The "winning" project is the one with the strongest combination of:
- Shipped or near-shipped Linear tickets
- Active Figma files with iterations or resolved comments
- Stakeholder engagement in Slack (feedback received, decisions made)
- Completed items from the running list that map to it

If two projects are close, pick the one with the most cross-functional visibility (eng + PM + design feedback all touching it). If the week was light across the board, pick the single most polished or interesting piece of work, even a small win is showcase-worthy.

State the chosen project clearly at the top so you can override if you wants something else.

---

## Step 2: Synthesize the work

For the chosen project, gather:
- **What progressed**, specific Linear tickets, Figma frames, decisions locked in
- **Key design moments**, what problem was solved, what tradeoffs were made, what changed from v1 to v2, what's still TBD
- **Stakeholder input**, notable feedback, validations, or pivots from Slack threads or comments
- **What's next**, open threads, upcoming reviews, who needs to weigh in
- **Collaborators**, anyone you worked closely with this week, for the cc list

For Figma links, **always link to the page or section that contains all the relevant components**, not a prototype or single-screen frame. Context gets lost otherwise.

---

## Step 3: Pick the right post shape

Match the post structure to the size of the work:

- **Fuller mode** (use when there are multiple explorations, decisions, or stakeholder threads): Sections for "What I've worked on", "Why this matters", "Next steps", and a CTA for feedback.
- **Lean mode** (use when the work is earlier-stage, a single exploration, or a quick concept share): One short paragraph framing the problem and what's being explored, then the link row.

Default to fuller mode if there's enough substance. Use lean mode when forcing structure would feel padded.

## Voice and style guide for the Slack post

**Tone**
- Informal, upbeat, team-chat friendly
- Direct and warm, never performative or braggy
- Honest about what's mid-fi, TBD, or "might be overkill", name tradeoffs out loud

**Openers** (rotate, don't repeat the same one weekly)
- "Hey team!!"
- "Hi team!!"
- "Hey y'all!"
- "Hey team"

**Structure conventions**
- Open with greeting + one-sentence project framing (what + why it matters in plain language)
- Optional context note when relevant (e.g. "not customer-facing yet", "early explorations")
- Use section headers like *What I've worked on*, *Why this matters*, *Next steps*, *Current plan*
- Bulleted lists for progress updates, with sub-bullets for variants/explorations
- Inline link row at the bottom: `[Loom](url) | [Figma](url) | [Doc](url)`
- cc collaborators with @ tags after the link row

**Hard rules**
- **Never use em dashes or en dashes (— or –).** Use commas, parentheses, or restructure the sentence.
- **No title case** that gives off AI vibes. Sentence case for everything except proper nouns.
- Use emoji sparingly. Only when they earn their place.
- Keep it skimmable. If a bullet is more than ~2 lines, tighten it.
- Always include a Figma link pointing to the **page or section with all components**, never a prototype or single screen.
- Always render the final Slack post inside a code block so you can copy it cleanly.

**Reference examples of your voice:**

*Example A (fuller mode, mid-project update):*
> Hey team!! Happy Friday Quick update on some explorations this week around moving from a reactive audit -> a proactive health dashboard.
> - Rethinking audits so users don't have to click into chat to generate a one-time snapshot
> - Exploring more proactive surfaces (e.g. smarter conversation starters, quick health cards, inline metrics)
> - Introducing a live dashboard view for health + opportunities instead of a static audit
>
> [Loom] | [Figma] | [Spec]
>
> Side note: [related context]
> cc. @collaborators

*Example B (fuller mode, early concept with explicit sections):*
> Hey team!! Quick walkthrough of some early explorations for [project], specifically [the key design move]. Note: [context like "not customer-facing yet"].
>
> *What I've worked on:*
> - Explored 3 directions for [thing]:
>    - Direction 1: [description]
>    - Direction 2: [description]
>    - Direction 3: [description]
> - Tried a [specific approach] (might be overkill vs. [alternative])
> - Kept everything mid-fi for now since [reason]
>
> *Why this matters:*
> - [user/strategic value point 1]
> - [user/strategic value point 2]
>
> *Next steps:*
> - Align with [team] on [open question]
> - Iterate on designs
> - Explore how this connects with @collaborator's work
>
> Would love any early reactions, especially on [specific question]!
>
> [Loom] | [Figma] | [Doc]
> cc. @collaborators

*Example C (lean mode, quick exploration share):*
> Hey team Sharing a quick Loom walking through my early exploration for [project]. Today, [problem statement in one sentence]. I'm exploring a way to [solution direction], and introduce features like [feature 1], [feature 2], and [feature 3] to this page.

## After presenting the showcase

Ask you:
> "Want to swap the project, tweak the post, or adjust the Loom outline? I can also pull more detail from any source if you want to go deeper on a specific moment."

If you approve, draft the post into **{{CHANNEL_NAME}}** (channel ID `{{CHANNEL_ID}}`) using slack_send_message_draft so you can review and send it yourself. If you explicitly ask for a different channel, use that one instead.

---

## Constraints

- **One project only.** Resist showcasing multiple things, the whole point is a focused highlight.
- **Show the thinking, not just the output.** Stakeholders care about the *why*, not just screenshots.
- **Never auto-send.** Always draft for review.
- **If the week was genuinely quiet** (OOO, research mode, between sprints), say so honestly and suggest skipping or showcasing a smaller in-progress piece. Don't manufacture momentum.
- **Always render the final Slack post in a code block** so it's one-click copyable.
