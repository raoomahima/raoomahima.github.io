Product marketing assets

Creates launch-ready product screenshots and GIFs from a demo account, then assembles them into an organized Figma file for release notes, docs, social and decks.

Installation

  1. Save the skill below as SKILL.md inside a folder named product-marketing-assets.
  2. Claude desktop: zip the folder, rename it to product-marketing-assets.skill, and add it under Settings > Skills.
  3. Claude Code: place the folder at ~/.claude/skills/product-marketing-assets/.
  4. Connect Figma, point it at a demo or staging account, and replace every {{PLACEHOLDER}}.

Usage

Name the feature and where the assets will be used. It returns screenshots, GIFs when you ask for them, and a Figma link.

/product-marketing-assets the results page for the release note
/product-marketing-assets a three-shot set and Figma file for the launch post
/product-marketing-assets a GIF of the onboarding flow plus screenshots
retake the hero shot with cleaner demo data and update the Figma file

# Product marketing assets

Produce consistent, on-brand screenshots and GIFs from a demo or staging account, then assemble them into a Figma file a marketer can pick up and use with no extra editing.

## Setup
| Field | Value |
|---|---|
| Environment | {{DEMO_ACCOUNT_OR_STAGING_URL}} |
| Output folder | {{OUTPUT_FOLDER}} |
| Figma team or project | {{FIGMA_PROJECT}} |
| Figma template or library | {{FIGMA_TEMPLATE_OR_LIBRARY}} |
| Viewport | 1440 x 900 (default) |
| Format | PNG for screenshots (2x when the tool allows), GIF for motion |

## Workflow
1. **Get the brief.** Ask for the feature, the one thing each asset should show, whether they want screenshots, GIFs or both, and where it will be used (release note, social, docs, deck). Default to screenshots, and add GIFs only when asked or when the feature is about motion or a multi-step flow. If the user already said, don't ask again.
2. **Use demo data only.** Never capture a real customer account. If the account isn't a demo or staging account, stop and ask.
3. **Stage the screen:**
   - Realistic, friendly data: believable names, round-ish numbers, no "test" or "asdf" strings.
   - The feature in its most useful state: populated, not empty, no error banners.
   - Close modals, toasts, cookie banners, and browser extensions.
   - Light theme unless told otherwise. Consistent zoom across a set.
4. **Frame and capture.** Crop to the feature, not the full app, unless the full layout is the point. Even padding around the subject. Capture the default state first, then interaction states that tell the story (hover, open menu, completed state).
5. **Check each image:** text legible at half size, no personal data, no cut-off elements, no cursor unless it adds meaning.
6. **Save the screenshots** as `<feature>-<state>-<usage>.png` in the output folder.
   **Record GIFs when asked.** Plan the shot first: one flow, 3 to 8 steps, under 10 seconds. Start from the staged default state, perform the steps at a calm pace with a short pause on the result, and use the browser's GIF recorder. Keep width at or under 1200px and the file under 5 MB when possible. Trim dead time at the start and end, and loop cleanly. Save as `<feature>-<flow>-<usage>.gif`. Check that text stays legible at half size and that no personal data appears in any frame.
7. **Build the Figma file.** Create a new file in {{FIGMA_PROJECT}} named `<feature> launch assets`, and lay out:
   - A cover frame with the feature name and one-line value.
   - One page per channel (release note, social, docs, deck), each with correctly sized frames.
   - The screenshots placed in frames with consistent padding, and GIFs added as image fills or linked next to a still frame of the same flow, using the team's library styles and fonts where available.
   - A short "notes" frame listing what each asset shows and its alt text.
   Use the Figma connector to create the file and upload the images. If the connector is unavailable, deliver the PNGs plus a list of frame sizes and say so.
8. **Deliver** the Figma link, the screenshot and GIF files, and a short list: asset, what it shows, suggested alt text.

## Sets
For a launch, offer three screenshots: the hero (the finished result), the before state (the problem), and one detail close-up. Add one GIF of the core flow when motion helps. Keep order and crop consistent in the screenshots, the GIF and the Figma frames.

## Rules
- Don't ship GIFs that show real customer data in any frame. Re-record instead of blurring.
- Don't edit the UI with devtools to fake states unless the user says so, and label any such asset as a mock.
- Don't ship numbers that aren't in the demo data. No invented metrics.
- Flag anything that looks unreleased or behind a flag before it goes in public material.
- Never overwrite an existing Figma file. Create a new one, or add a clearly named page.
- Don't share the Figma link outside the team unless the user asks.
