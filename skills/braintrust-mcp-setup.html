Braintrust MCP setup

A guide to connecting Claude to Braintrust so you can query logs, traces and experiments in plain language.

Installation

  1. Pick your endpoint. US: https://api.braintrust.dev/mcp. EU: https://api-eu.braintrust.dev/mcp. BYOC: copy the MCP URL from Settings > Data plane in Braintrust.
  2. Add the server in Claude. Use HTTP transport. Claude Code: claude mcp add --transport http braintrust https://api.braintrust.dev/mcp Claude chat and Cowork: add a custom connector with the endpoint URL. Claude guide · Braintrust guide
  3. Sign in. Use OAuth: approve access on the Braintrust page that opens. No API key needed. The server acts with your account's permissions.
  4. Verify the connection. In Claude Code, run claude mcp list to confirm braintrust shows as connected. In Claude chat and Cowork, check that the connector shows as active.
  5. Require confirmation for write tools in your client. They act on your organization with your permissions.
  6. Test it. Ask Claude the first prompt below. You should get your projects back.

Usage

Swap in your agent or feature area for [agent]. Each prompt pulls real user messages from your logs.

1. SURFACE "DO IT FOR ME" ACTIONS

What types of direct-action requests are users making in [agent / feature area]? Pull a sample of incoming user messages and identify where users are asking the agent to execute something on their behalf rather than guide them.
2. RECOMMENDATION -> COWORK LOOP

How are users coworking with [agent] after it delivers a recommendation? Look for patterns: do they try to hand execution back, verify their own work, ask what to do next, or build on the recommendation with more context?
3. VERIFICATION LOOP

Find conversations where users return to [agent] after making a change to check if they did it right. What percentage of sessions include a "did I fix this" or re-audit message after the agent gave advice?
4. CAPABILITY GAP DISCOVERY

Where are users hitting a wall with [agent]? Pull messages where the user tried to get the agent to do something it couldn't. Look for fallback signals like "how do I do it myself" right after a failed action request?
5. CREATION REQUESTS BY TYPE

What are users asking [agent] to create from scratch? Break down creation requests by type (e.g. campaign, segment, flow, email content) and note whether users provide a detailed brief, a reference example, or just a one-liner.
