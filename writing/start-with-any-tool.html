Rotating between Claude, Codex, and Cursor

I've used Claude, Codex, and Cursor to ship front-end changes, and I rotate between them. I used to use Cursor a lot more. Lately it's Codex and Claude, a couple of PRs in one and a couple in the other.

At this point they're converging. Each one can read the code, make the change, run the tests, and open a PR. What's left is which interface you like working in. So this isn't a ranking. It's what pulls me to each one, and what I'd tell a designer picking their first.

Claude is where I do more than code. I use it for design and prototyping too, so I can move between exploratory work and production improvements without changing tools.

It's connected to Linear and Figma, so it pulls context from the ticket and the design instead of me pasting it in. When it opens a PR, the changes and the linked PR show up right in the interface, and I can jump to GitHub from there.

The bigger change is how much of the git work it handles now. I used to keep a terminal open side by side and type the commits, pull requests, and branch switches myself. Then I'd go into GitHub and paste in the description it had written.

Now Claude creates its own branch, makes the commits, explains what's in each one, and updates the PR description in GitHub directly. In Claude Code you can ask for all of that in one line:

create a pr for my changes

In Codex it's easier to see each branch and switch between them.

In Claude I once got confused because a single chat was talking about two branches and switched between them. I lost track of which one I was on. In Codex the branches are easier to tell apart visually, so I don't commit to the wrong one by mistake. The branch controls sit right in the chat, with a worktree option and a starting branch under the message box, and a Create branch here button in the header.

I also like the terminal experience in Codex and Cursor.

The fix for my mix-up wasn't switching tools. It was giving each branch its own copy of the code. A git worktree is a separate checkout of the same repo, so two sessions can run side by side without touching each other's files.

All three tools support this now. In Claude Code:

claude --worktree banner-cleanup

Codex has the same --worktree flag in its CLI, and a Worktree option in the app. Cursor has a /worktree command and an Agents Window that lists local, worktree, and cloud agents together. Each also runs cloud sessions, where every task gets its own branch on a separate machine.

One detail is easy to miss. In the Claude desktop app, worktrees are off by default. Several sessions in the same project folder will edit the same files unless you turn it on. I use separate worktrees on purpose now.

The tools are only part of why I can ship quickly. My company has a team that sets up testing and the environment I need, so I can get a PR ready faster.

Honestly, you can start with any of them. It depends on what's already in your toolset.

If you already chat and work with Claude, switch over to Claude Code and explore from there.
